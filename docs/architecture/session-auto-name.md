# 会话自动命名（F13）设计文档

> 实现位置：[apps/desktop/src/sessionAutoName.ts](../../apps/desktop/src/sessionAutoName.ts)（纯函数模块）+ [apps/desktop/src/App.tsx](../../apps/desktop/src/App.tsx) `send()` 内的触发点。
> 特性编号 F13。参考 Claude Code / Codex CLI 的命名思路，但**完全本地化**：无 LLM 依赖、零成本、<1ms。

## 1. 行为概述

用户在新会话发出**第一条消息**时，把消息内容压缩成一个简短标题（如「帮我看下登录为什么 401」→「登录为什么 401」），自动替换默认的「新会话」标题。用户手改过的标题**永不覆盖**。

## 2. 完整链路

```
App.tsx send()
  ├─ 触发条件：messages().length === 0（本会话首条消息）
  │            且 isAutoGeneratedTitle(session.title)（标题仍是自动默认名）
  ├─ 生成：smartTitleFromMessage(content)        ← 纯前端启发式，见 §3
  ├─ 防降级：结果本身仍是默认名格式 → 放弃改名
  ├─ 写回：SDK c.renameSession(sid, title)
  │         → PATCH /sessions/{id}  body {title}   ← sidecar 落 SQLite sessions.title
  └─ 刷新：refreshSessions()
  整体 fire-and-forget：任何失败 console.warn 后静默，不影响发消息主流程
```

## 3. 标题生成算法（`smartTitleFromMessage`）

四步启发式：

1. **取首句**：按 `\n` `\r` `。？！?!.` 任意一个切分，取第一段并 trim；
2. **迭代去客套前缀**：维护一张中英文前缀表（约 50 个），循环剥除直到不再匹配（处理「请帮我看下…」这种叠词），守卫上限 10 轮防死循环。前缀表**长前缀优先**排列（先「能不能帮我」后「帮我」，避免短的先匹配吃掉一半）：
   - 中文：能不能帮我 / 可以帮我 / 帮我看下 / 帮我写 / 请你 / 麻烦 / 我想 / 想要 …
   - 英文：`Please ` / `Can you ` / `Help me ` / `I want to ` …（大小写不敏感）
3. **限长**：含 CJK 字符 → 最长 **14 字**；纯西文 → 最长 **50 字符**；超长截断加 `…`；
4. **兜底**：清洗后为空或仅剩 1 个字符 → `fallbackTitle()` = `新会话 MM-DD HH:mm`（带时间戳，避免又叫「新会话」做无意义覆盖）。

## 4. 「可覆盖」判定（`isAutoGeneratedTitle`）

只覆盖**自动生成的默认名**，保护用户手改的标题。当前 maxian 的默认名格式散落在多处（前端两处 createSession + sidecar 后端默认），白名单需全部覆盖：

| 格式 | 来源 |
|---|---|
| `新会话` / `新对话` | sidecar `sessionManager.ts` 后端默认 |
| `会话 HH:MM` | 前端 Code 模式 createSession |
| `对话 HH:MM` | 前端 Chat 模式 createSession |
| `新会话 MM-DD HH:mm` / `新对话 MM-DD HH:mm` | 本模块 fallbackTitle |

⚠️ **维护注意**：任何地方新增/修改默认标题格式，必须同步更新 `isAutoGeneratedTitle` 的正则白名单，否则新格式的会话将永远不会被自动命名（或反过来把它当用户标题保护起来）。

## 5. 设计取舍记录

- **为什么不用 LLM 命名**（Claude Code 用 LLM）：标题在**发消息那一刻**就要出现，LLM 命名有延迟和成本，且 sidecar 可能处于 Echo/未配置状态；启发式 <1ms、离线可用、效果对中文输入足够好；
- **为什么在前端而不是 sidecar**：复用前端已有的 session 状态（messages 计数、title），且 fire-and-forget 失败不影响主流程；sidecar 侧做需要在消息入库路径上加 hook，侵入更大；
- **为什么 fallback 带时间戳**：覆盖成同样的「新会话」毫无意义，带时间戳至少让多个未命名会话可区分。

## 6. 测试要点

- `smartTitleFromMessage('帮我看下登录为什么 401')` → `登录为什么 401`；
- 叠词剥除：`请帮我帮我写个脚本` → `写个脚本`；
- 英文：`Can you help me fix the build error in CI pipeline and ...`（>50 字符）→ 截断加 `…`；
- 全客套输入：`帮我` → fallback `新会话 MM-DD HH:mm`；
- 用户已手改标题 → 不触发改名；第二条消息 → 不触发。

## 7. 迁移备注（九思客户端替换计划）

九思客户端（jiusi-desktop）**没有此功能**（grep `autoName|smartTitle|自动命名` 零命中）——按 [docs/migration/jiusi-client-replacement.md](../migration/jiusi-client-replacement.md) 迁移时需移植：
- `sessionAutoName.ts` 为纯函数模块，**原样拷贝**即可；
- 触发点插入九思 App.tsx 的 `send()`（同样的「首条消息 + 默认名」条件）；
- ⚠️ 九思的默认标题格式需排查后补进 `isAutoGeneratedTitle` 白名单（九思的 createSession 默认名可能与码弦不同）；
- 九思 SDK 同源，`renameSession`（PATCH /sessions/{id}）应已存在，移植时确认。
